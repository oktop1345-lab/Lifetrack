# Трекер жизни (PWA для iPhone)

Личное приложение: привычки, тренировки, учёба, финансы, экранное время, диаграммы и AI-ассистент.
Ставится на экран «Домой» из Safari. Без бэкенда, без регистрации, без App Store.

## Владелец и стиль работы

- Владелец не разработчик, у него только iPhone (нет Mac, нет локального терминала).
  Объяснять простым языком, по шагам. Не предлагать ничего, что требует компьютера.
- Результат владелец смотрит только по ссылке GitHub Pages в Safari на iPhone.
- После каждого изменения: `npm run test`, `npm run build`, без ошибок, затем коммит и push
  (деплой запускается сам), затем короткое объяснение «как посмотреть».
- Не добавлять зависимости и функции, которых не просили.
- Интерфейс на русском языке.

## Стек (зафиксирован)

- Vite + TypeScript, без UI-фреймворков (обычный DOM, маленькие функции-помощники).
- Dexie (IndexedDB) для данных.
- Chart.js через npm, входит в сборку. Никаких CDN, внешних шрифтов и скриптов.
- vite-plugin-pwa: манифест + service worker (precache всей сборки, офлайн после первой загрузки).
- Vitest для тестов логики (только dev-зависимость).
- Деплой: GitHub Actions -> GitHub Pages. Репозиторий `oktop1345-lab/Lifetrack`, ветка `main`.
  `base` в Vite берётся из переменной `BASE_PATH`, её задаёт workflow как `/<имя-репозитория>/`.
  Адрес приложения: https://oktop1345-lab.github.io/Lifetrack/

## Жёсткие правила

- Все данные только на устройстве (IndexedDB). Никакой аналитики, никаких сторонних запросов,
  кроме запросов к выбранному AI-провайдеру.
- API-ключ хранится только на устройстве (таблица `settings`), никогда не попадает в репозиторий,
  в экспорт по умолчанию не включается (при экспорте спрашивать отдельной галочкой).
- AI получает сводки за период, а не всю базу. Заметки и отдельные записи в чат не отправляются.
  Исключение по просьбе владельца: причины «тянет скроллить» (заметки к записям `urges`) - AI должен
  помнить, когда и почему тянет. В чат идут до 5 последних, в текст поддержки - до 8 последних за 30 дней.
- Офлайн: всё, кроме AI, работает без сети. AI без сети показывает понятное сообщение.
- Ошибки сети/CORS/неверного ключа показывать человеческим текстом, не пустым экраном.
- Mobile-first: нижняя навигация, зоны нажатия от 44px, safe-area (`env(safe-area-inset-*)`).
- Тема по умолчанию светлая, даже если iPhone в тёмном режиме (просьба владельца). В настройках можно
  выбрать «Тёмная» или «Как в iPhone». Логика - `core/theme.ts`: класс `theme-dark` на `<html>`,
  выбор в настройке `theme` и копия в localStorage (чтобы экран не мигал при запуске).
  В CSS тёмные цвета - только под `:root.theme-dark` / `.theme-dark ...`, без `prefers-color-scheme`.
- Не обещать блокировку приложений: PWA этого не умеет. В интерфейсе отсылать к встроенному
  «Экранному времени» iPhone.

## Оформление (в духе Notion, по просьбе владельца)

- Белая страница (`#ffffff`, тёмная `#191919`), тёплый почти чёрный текст, тонкие рамки 1px,
  без теней и заливок у карточек. Радиусы: карточки 10px, кнопки и поля 8px, метки 4px.
- Акцент - синий (`--accent-fill`): главная кнопка, галочки, выбранные метки.
- У каждого раздела свой цвет и пастельный фон: `--c-<раздел>` и `--bg-<раздел>`;
  класс `.m-<раздел>` задаёт `--m` и `--m-bg` для значков (`badge`), меток (`tag`), полосок (`meter`).
  Разделы: `habits` (зелёный), `workouts` (оранжевый), `study` (синий), `finance` (фиолетовый), `screen` (розовый).
- Привычки отмечаются квадратной галочкой, выполненные зачёркиваются.
- Длинные значения (деньги) показывать списком «подпись - значение» (`props`), короткие - плитками (`tiles`).
- Ассистент в чате пишет без «пузыря», сообщение пользователя - серый блок справа.
- Все переменные темы - в `src/styles/base.css`, компоненты - в `src/styles/components.css`.

(их и тестируем). `view.ts` экспортирует `render(container)`. Модуль подключается одной строкой
в `routes.ts` и своими таблицами в `db.ts`. Общее - в `core/`.
Модули не импортируют друг друга, кроме: `today` (читает логику и открывает формы всех разделов),
`ai/context.ts` (логика всех разделов), `assistant` (берёт `today/data.ts`),
`screen` (логика привычек - для связи и для таймера, `clock` из учёбы).

## Данные (Dexie, база `life-tracker`, версия схемы 2)

Общие правила:
- `id` - строка `crypto.randomUUID()`.
- День - строка `YYYY-MM-DD` в местном времени. Момент времени - ISO-строка.
- Деньги - целое число в минимальных единицах (тиыны/копейки/центы), без дробей.
- Длительность - целые минуты.
- Новая таблица или индекс = новая версия `db.version(n)` и `SCHEMA_VERSION`, старые версии не трогать.
  Обновление с версии 1 на 2 проверено: старые данные сохраняются.

| Таблица | Поля | Индексы |
|---|---|---|
| `settings` | `key`, `value` | `key` |
| `habits` | `id`, `name`, `schedule: {type:'daily'} \| {type:'weekdays', days:number[]}` (1=Пн..7=Вс), `createdAt`, `archivedAt?` | `id` |
| `habitChecks` | `id`, `habitId`, `date` | `id`, `[habitId+date]` (уникальный), `date` |
| `workouts` | `id`, `date`, `type`, `note?`, `exercises: [{name, sets:[{weight, reps}], bodyweight?}]` (у «своего веса» `weight` - доп. вес) | `id`, `date` |
| `studySubjects` | `id`, `name`, `createdAt`, `archivedAt?` | `id` |
| `studyGoals` | `id`, `subjectId`, `title`, `targetMinutes`, `deadline?`, `createdAt` | `id`, `subjectId` |
| `studySessions` | `id`, `subjectId`, `goalId?`, `date`, `minutes`, `note?` | `id`, `date`, `subjectId`, `goalId` |
| `categories` | `id`, `name`, `kind:'income'\|'expense'`, `color` (номер цвета 0..7) | `id`, `kind` |
| `transactions` | `id`, `kind:'income'\|'expense'`, `amount`, `categoryId`, `date`, `note?` | `id`, `date`, `categoryId` |
| `savingsGoals` | `id`, `name`, `target`, `saved`, `deadline?`, `createdAt` | `id` |
| `screenDays` (v2) | `date`, `totalMinutes`, `apps: [{name, minutes}]`, `sleepMinutes?`, `source:'manual'\|'screenshot'` | `date` (ключ) |
| `urges` (v2) | `id`, `at`, `trigger:'boredom'\|'stress'\|'tired'\|'bedtime'\|'other'`, `note?` (причина), `insteadOf?`, `coach?` (показанный текст поддержки) | `id`, `at` |

Ключи `settings` (тип `AppSettings` в `core/settings.ts`): `currency` (по умолчанию `KZT`), `monthlyBudget`,
`ai` (`{provider, configs: {<провайдер>: {apiKey, model, baseUrl?}}}` - у каждого провайдера свой ключ и модель),
`studyTimer` (`{subjectId, goalId?, startedAt}` - таймер считается от времени старта, потому что iOS
останавливает приложение в фоне), `screenLimitMinutes`, `bodyWeightKg` (вес тела для объёма упражнений со своим весом), `theme` (`'light'|'dark'|'auto'`, по умолчанию `light`), `firstRunAt`, `lastBackupAt`, `backupSnoozedAt`.

История чата с AI и недельный отчёт живут только в памяти до закрытия приложения (в БД не пишутся).

## Бэкап

- Экспорт: один JSON `{app, schemaVersion, exportedAt, tables: {имя: [...]}}`. Экспорт проходит по всем
  таблицам `db.tables` автоматически - новый модуль попадает в бэкап без правок.
- Импорт: проверка `app` и `schemaVersion` (старые бэкапы читаются), затем полная замена данных
  в одной транзакции (с подтверждением). Настройки из файла накладываются поверх текущих; если в файле
  нет ключей, ключи на устройстве сохраняются.
  `firstRunAt`, `lastBackupAt`, `backupSnoozedAt`, `studyTimer` в файл не идут.
- На iPhone экспорт открывает меню «Поделиться» (Сохранить в Файлы), иначе - обычное скачивание.
- Напоминание: если с `lastBackupAt` прошло больше 7 дней - плашка при открытии приложения
  (фоновые уведомления в PWA на iOS ненадёжны, поэтому напоминание внутри приложения).
- При запуске: `navigator.storage.persist()`.

## AI

- Провайдеры: Anthropic (`anthropic-dangerous-direct-browser-access: true`), OpenAI, OpenRouter,
  Gemini, свой OpenAI-совместимый endpoint (base URL + модель).
- Единый интерфейс: `streamChat(ai, {system, messages, onDelta, signal})`. Потоковый вывод через SSE,
  если поток недоступен - обычный ответ целиком. Запросы через `fetch`, без SDK (лишняя зависимость).
- Картинки: `ChatMessage.images` (`{mime, data}` в base64). Anthropic - блок `image`, OpenAI-совместимые -
  `image_url` с data-адресом, Gemini - `inline_data`.
- Anthropic: версия API `2026-10-21`, модель по умолчанию `claude-opus-5-5`, `max_tokens: 64000`,
  без `temperature` и без параметра `thinking`. Для моделей из `ANTHROPIC_FALLBACK_MODELS` шлём
  `fallbacks: "default"` + beta `server-side-fallback-2026-07-01`; при ответе 400 повторяем без них.
- Провайдер по умолчанию - Google Gemini (выбор владельца). Запрос: `system_instruction` + `contents`,
  ключ в заголовке `x-goog-api-key`, поток через `?alt=sse`.
- У OpenAI, OpenRouter и Gemini модели по умолчанию нет (названия быстро устаревают): в настройках
  кнопка «Выбрать из списка» грузит модели, доступные с ключом пользователя (`listModels`).
- Перед изменением кода провайдеров сверять актуальные API (модели, заголовки) с документацией.
- Контекст чата: `buildContext(data, today, days)` - сводка за 7/30/90 дней (выбирается в чате, по
  умолчанию 30): привычки (проценты, серии), тренировки (число, типы, объём по неделям, лучшие результаты),
  учёба (время по предметам, цели), финансы (суммы, категории, бюджет, цели), экранное время (среднее,
  лимит, приложения, триггеры). В чате есть раскрывающийся блок «Что видит AI» с этим текстом.
- Проверено только на поддельных ответах провайдеров (настоящего ключа в среде разработки нет).

## Диаграммы (правила для всех модулей)

- Chart.js подключается только через `core/charts.ts`; новые типы регистрировать там же.
- Цвета берутся из CSS-переменных темы в момент отрисовки (`cssVar`); при смене темы `main.ts`
  перерисовывает экран. Служебные цвета: `--chart-muted`, `--chart-grid`, `--chart-axis`.
- Одна серия = цвет раздела (`--c-<раздел>`).
  Несколько категорий = фиксированный порядок из 8 цветов `--series-1..8` (проверен на различимость
  при дальтонизме), цвет закреплён за категорией (`Category.color`, тип тренировки) и не меняется
  при фильтрах. Лишнее сворачивается в «Прочее» (`--series-other`).
- Тепловая карта: один оттенок от светлого к насыщенному, переменные `--heat-<раздел>-1..4`.
- Столбцы не толще 24px, скругление 4px на конце, сетка тонкая сплошная, без двух осей Y на одном графике.
- Анимация выключена (экран перерисовывается целиком после каждого действия).
- Под диаграммой - `dataTable()` («Показать числа») или подписи со значениями (`legend`);
  подсказка по касанию - на всю колонку.
- Диаграмму создавать через `mountChart` (после вставки холста на страницу) и уничтожать (`destroy`)
  при перерисовке и уходе с экрана.

## Как устроены разделы

- **Привычки.** Привычка считается с дня создания. Серия не обрывается, пока сегодняшний день не отмечен;
  незапланированные дни серию не прерывают. Удаление привычки удаляет и её отметки.
  Диаграммы: тепловая карта за 53 недели, столбцы за 12 недель, фильтр по привычке.
- **Финансы.** Стандартные категории создаются при первом открытии (`ensureCategories`). Листание по месяцам,
  бюджет на месяц («сколько в день до конца месяца»), операции по дням, цели накоплений с пополнением.
  Диаграммы: кольцо расходов по категориям, доходы и расходы за 6 месяцев.
- **Тренировки.** Типы фиксированы (`WORKOUT_TYPES`, новые только в конец - по номеру закреплён цвет;
  последний добавлен «Свой вес»). Объём = нагрузка × повторения. При выборе знакомого упражнения
  подставляются подходы и отметка «свой вес» с прошлого раза.
  Собственный вес (просьба владельца): у каждого упражнения переключатель «С весом / Свой вес»;
  по названию (подтягивания, отжимания, брусья, пресс, планка...) он включается сам (`looksBodyweight`).
  Для своего веса колонка веса = доп. вес (жилет), обычно пусто. Нагрузка подхода = вес тела + доп. вес
  (`setLoad`); пока вес тела не указан (карточка «Собственный вес»), такие подходы в кг не идут, только в
  повторения (`bodyweightReps`). Старые записи без отметки считаются «своим весом», если веса нет ни в
  одном подходе (`isBodyweight`). Прогресс такого упражнения - лучшие повторения в подходе.
  Диаграммы: объём за 12 недель, линия прогресса по упражнению, кольцо по типам за 90 дней.
- **Учёба.** Предметы, цели (в часах, хранятся в минутах), занятия. Таймер живёт в настройке `studyTimer`;
  «Завершить» открывает форму занятия с насчитанными минутами. Удаление предмета удаляет его цели и занятия.
  Диаграммы: часы по предметам (7/30/всё время), полоски прогресса по целям.
- **Экранное время.** Ручной ввод за день (общее время, приложения в формате `ч:мм`, сон). Ввод по скриншоту:
  картинка уменьшается до 1600px, отправляется AI, ответ разбирает `parseScreenReply`, затем открывается
  та же форма для проверки; скриншот не хранится; при ошибке предлагается ручной ввод.
  Лимит в сутки и серия дней ниже лимита (день без записи обрывает серию).
  «Тянет скроллить»: запись (время, триггер, причина) сохраняется сразу, таймер на 10 минут, привычки
  из списка можно отметить прямо там. Пока идёт таймер, показывается текст поддержки НА АНГЛИЙСКОМ
  про дисциплину и что сделать вместо ленты: AI получает `COACH_SYSTEM` и `urgeMemory` (текущая причина,
  итоги за 30 дней по триггерам/времени суток/дням, до 8 прошлых записей с причинами, открытые привычки).
  Без интернета, без ключа или при ошибке AI - встроенный текст из `FALLBACK_COACH` по триггеру.
  Показанный текст сохраняется в `urge.coach` и виден в карточке записи.
  Диаграммы: динамика за неделю/месяц с линией лимита, приложения, тепловая карта, сравнение дней
  (с тренировкой/без, все привычки/не все, сон от 7 часов/меньше; нужно по 3 дня в группе).
  Модуля сна нет: сон - необязательное поле в записи дня (допущение согласовано с владельцем).
  Недельный отчёт AI получает только `weekSummary`.
- **Сегодня.** Привычки на сегодня, быстрые кнопки (расход, тренировка, учёба, «тянет скроллить»),
  мини-графики по разделам за 7 дней, обзор недели и месяца с изменением к прошлому периоду.
